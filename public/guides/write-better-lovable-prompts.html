How to Write Better Lovable Prompts

Clear prompts give better results in fewer messages. Use this simple formula and the examples below.

The simple formula

A good prompt answers four questions: Where (which page or section), What (the change), How it should look or behave, and What must stay the same.

Example: “On the pricing page, add a third plan card called Team, $49 per month, with the same style as the other two. Keep the other cards unchanged.”

Ten habits that save messages

  1. Ask for one feature per message.
  2. Name the page or component you mean.
  3. Describe the result, not the code.
  4. Paste the exact error text when something breaks.
  5. Attach a screenshot for visual changes.
  6. Use Plan mode for anything bigger than a small edit.
  7. Say what must not change.
  8. Give real sample content (names, prices) instead of “some text”.
  9. Check the preview before asking for the next change.
  10. If it goes wrong twice, restore an earlier version and rephrase instead of stacking fixes.

Prompts for common tasks

  • New page: “Add an About page with a heading, two paragraphs about our team and a photo grid. Link it in the top menu.”
  • Data: “Save contact form messages so I can see them later. Show them in a table on an Admin page.”
  • Style: “Use a dark background, white text and one accent colour (#00C2A8) across the whole site.”
  • Mobile: “On phones, stack the three feature cards vertically and make the menu a button.”

Frequently asked questions

How long should a Lovable prompt be?

Long enough to name the page, the goal and the details that matter — usually three to eight sentences. One clear request per message works better than a long list.

Why does Lovable change things I did not ask for?

Usually because the request was broad. Name the exact page or section and add “don’t change anything else”.

Should I use Plan mode?

Yes for bigger features. Agree the plan first, then approve it, so the build follows what you actually want.
